# 图形编辑器的权限与账号

给部署和运维用。三个角色按现场分工划分：

| 角色 | 谁用 | 能做什么 |
|---|---|---|
| **使用者** operator | 现场操作人员 | 看流程图和运行状态、启停调度、改现场配置 |
| **开发者** developer | 负责某个项目的人 | 加上：在**授权的项目**里改流程图和点位、跑演练、导入导出；其他项目只读 |
| **维护者** maintainer | 你自己 | 全部，且不受项目范围限制 |

逐项对照：

| 操作 | 使用者 | 开发者 | 维护者 |
|---|---|---|---|
| 看流程图 / 运行状态 | ✓ | ✓ | ✓ |
| 启动·暂停·停止调度 | ✓ | ✓ | ✓ |
| 改现场配置（`robot_config`） | ✓ | ✓ | ✓ |
| 演练 | ✗ | ✓ | ✓ |
| 改流程图 / 点位、导入导出 | ✗ | 仅授权项目 | ✓ |

**为什么改 `robot_config` 使用者也能做**：它是「🤖 运行控制」面板里的「配置文件」，
内容是机器人 IP、端口、MQTT 地址，Docker 下写的是外部挂载的 `/config/robot_config.json`。
换了机器人、改了网段，现场就得动它——这属于现场运维，和启停调度同性质，
不是开发动作。所以它跟着 `RUN_CONTROL` 一起开放，而不是锁给维护者。

（保留成独立的 `EDIT_ROBOT_CONFIG` 权限点而不是并进 `RUN_CONTROL`，
是为了以后想收紧时改 `ROLE_PERMISSIONS` 一行就够。）

完整的权限点在 `infrastructure/auth.py` 的 `ROLE_PERMISSIONS`，那里是唯一的权威定义。

## 默认不启用，页面上不会有任何变化

**没设口令时权限管理是关闭的**，所有人拥有全部权限——也就是加这个功能之前的行为，
编辑器右上角**不会出现登录入口**。这样现有现场升级后不会突然什么都改不了
（他们手上本来也没有口令）。

想知道当前是什么状态：进页面时底部日志区会说；启动服务也会打一行。

## 启用：本机明文 → 密封包

明文只留在维护者电脑上的 `PACK_DELETE/` 目录，**打包发给现场 / 打 Docker 镜像前整夹删掉**：

| 本机文件（打包删除整个目录） | 用途 |
|---|---|
| `PACK_DELETE/auth_accounts.json` | 明文账号、口令 |
| `PACK_DELETE/auth_private.json` | 签名私钥（首次生成脚本会建） |
| `PACK_DELETE/make_auth_pack.py` | 生成命令 |
| `PACK_DELETE/README.md` | 本目录说明 |

现场只认密封包（哈希 + 签名，打开是乱码）：

1. 有 `/config/auth_accounts.pack` 且验签通过 → 用它（整份替换）
2. 否则用 `infrastructure/auth_accounts.pack` 出厂包
3. 覆盖包损坏或不是这把私钥签的 → 当没有，退回出厂

`/config/robot_config.json` 里塞角色不会生效，两份密封包也不和它合并。

改账号、忘了口令：只改本机明文，再生成，把新包拷到对方 `/config`：

```bash
python3 PACK_DELETE/make_auth_pack.py
python3 PACK_DELETE/make_auth_pack.py --out /config/auth_accounts.pack
```

明文里 `keys`（口令登录）和 `users`（具名账号）任一有口令即启用，两种可以同时开：

```json
{
  "anonymous_role": "operator",
  "session_timeout_minutes": 480,
  "keys": {
    "maintainer": { "password": "你的维护者口令" },
    "developer": [
      { "name": "kaiao", "password": "口令A", "allowed_projects": ["KAIAO_FLOW"] },
      { "name": "const", "password": "口令B", "allowed_projects": ["CONST_FLOW"] }
    ]
  },
  "users": [
    { "name": "zhang", "role": "developer", "password": "明文口令",
      "allowed_projects": ["KAIAO_FLOW"] }
  ]
}
```

已有 `password_hash`、不知道明文的条目可以保留哈希；新写 `password` 会在生成时换成哈希并丢掉明文。
临时停用某个账号：`"enabled": false`。

生成后拷到现场（或更新镜像里的出厂包），刷新浏览器右上角出现「登录」。
服务按密封包修改时间自动重载，不用重启 `main.py`。

登录框长什么样，取决于配了什么：

| 配了什么 | `login_mode` | 登录框 |
|---|---|---|
| 只有 `keys` | `key` | 只输口令 |
| 只有 `users` | `user` | 账号 + 口令 |
| 两种都有 | `both` | 可切换「账号登录 / 口令登录」，默认账号 |
| 都没有 | `off` | 没有登录入口 |

要用具名账号对照「是谁改了流程图」，把人写进 `users`。保存、激活流程时，
后端日志会带上这个名字（口令登录则用条目上的 `name`，例如 `kaiao`）。

`allowed_projects` 决定开发者能改哪些项目。`keys.developer` 写成数组即可多条口令。

现场没有「设置口令」或「查出全部口令」的接口。没有私钥就无法生成能用的覆盖包。

## 什么时候会退出登录

四种情况，登录弹窗里也写着：

- **关闭浏览器标签页** —— 立即退出（令牌存在 `sessionStorage`，不落盘）
- **连续 480 分钟没有任何操作** —— 自动退出；有操作就一直续期，不会把正在改图的人踢出去
- **重启主程序或编辑器服务** —— 全部退出（会话只在内存里）
- **手动点右上角的「退出」**

超时时长改 `session_timeout_minutes`。

## 需要给多个人分别开号时

项目可以按口令拆（`keys.developer` 数组），人则写进 `users`，便于对照是谁改的。
`users` 与 `keys` 同时存在时，登录框可以在两种方式之间切换。改完本机明文后重新生成密封包。

## 为什么不放进 robot_config、也不合并

权限密封包**没有**放进 `robot_config.json`，也不走 `load_config()`。

`load_config()` 是分层合并的，优先级 `infrastructure` ← 项目 ← `/config`（Docker 挂载），
最高那层就在客户机器上。只要读取走了这个函数，对方故意在 `/config/robot_config.json` 里
加一段 `role: maintainer` 就会被合并进来。

所以账号只认 `auth_accounts.pack`：`/config` 有合法签名的才整份覆盖出厂包，
`robot_config.json` 里塞 `auth` 段不会生效。没有私钥签不出能用的覆盖包。
升级镜像会更新出厂包；现场 `/config` 里那份覆盖还在。

## 这套机制防什么、不防什么

**防**：误操作、越权使用、分工混乱。操作人员点不到改流程图的按钮，
某个项目的开发者动不了别人的项目。

**不防**：拿到 root 的人。能进容器改文件的人总能绕过任何本地校验——
改掉 `auth.py` 里的判断就行。这属于代码保护的范畴，是另一件事
（Cython 编译、机器绑定授权等，见下节）。

所以定位要清楚：这是**管理机制**，不是对抗手段。

## 关于代码保护（尚未实施）

只要软件在对方机器上运行，对方就一定能拿到能运行的那份东西：`docker save` 导出镜像
解包 tar、`docker cp` 直接拷、`docker exec` 进去看，任何一条都够。这是原理性的。

能做的是把成本抬高到"不值得抄"：

| 手段 | 挡得住 | 代价 |
|---|---|---|
| 删 `.py` 只留 `.pyc` | 随手翻看的人（可反编译还原） | 几乎为零 |
| Cython 编译成 `.so` | 绝大多数人，要专业逆向 | 中：构建变复杂、现场排查变难 |
| 机器指纹绑定授权 | 复制到别的电脑直接用 | 低 |
| 启动时校验文件哈希 | 改了代码还想正常跑（root 可绕，但留痕） | 低 |

真正值得编译的是业务资产：`programs/` 下各项目的编排逻辑、`core/` 的流程引擎。
`network/`、`hardware/` 偏通用，编了收益不大还妨碍排查。

## 前端的置灰只是体验

工具栏按钮按角色置灰、`title` 里说明原因，是为了别让人点到注定被拒的按钮。
**真正的拦截在后端逐接口做**（`network/flow_api_server.py` 的 `_PERM_GET` / `_PERM_POST`
两张表 + `_require()`），所以用 curl 绕过前端也拿不到额外权限。

加新接口时记得在那两张表里登记，漏登记的 POST 路径会直接 404 而不是放行——
这是故意的，宁可挡住也不要默认放开。
