# 更新日志

本机与 GitHub 共用这一份版本记录（从 **3.0.2** 起）。  
当前版本见仓库根目录 `VERSION`。历史功能说明仍在同目录的 `新功能清单.md`，本文件只记版本迭代。

## 3.0.4 — 2026-10-13

### ZHANTING

- 新增图形化项目「展厅」：人工上料确认 → 机械臂送瓶开盖 → 第一杯分液 → 并行（第二杯分液 / 检测放料移位）→ 并行（关盖归位 / 检测倒废液）；每次跑一轮，不自动重复
- 机器人操作、导航、机械臂 HTTP、PLC 全部用通用功能块，项目自己零专有节点（`NODE_TYPE_SCHEMAS` 为空）
- PLC 走 S7（`192.168.217.40`、DB2）：19 个 INT 输入主动查询、9 个 BOOL 输出主动改写；点表里的 40000～40018 / 0～8 只是逻辑点号，实际按现场 DB2 字节与位寻址，9 个输出共处两个字节故置位走读改写
- 样品二维码占 10 个连续字，用单次请求读完存进流程变量 `qr_codes`，逐点读会拼出新旧混合的码
- 机械臂 `arm_url` 和 S7 的 rack/slot 等待现场核对，README 列了一张待核对清单；演练不访问 PLC 与 HTTP，地址未填也能走通
- 运行控制的 Mock 同时拉起 `mock_http_service`（`http://127.0.0.1:18080/`），机械臂 HTTP 在没接真机时按动作完成返回；`arm_url` 指向该地址

### XINXIANG

- 新增图形化项目：定量分液与检测放料位移并行，随后放料、检测启动、取料位移、取料、检测取料完成；`START_WORKING` 连机器人，`PROCESS_BEGINS` HTTP 开跑流程
- 检测模块 PLC：本机恢复为 Modbus TCP 服务器（对方是客户端），与旧 `PLCServer` 一致
- 检测放料位移：本机先把 4003 写成 1，再等对方改成 2（不再空等对方把 0 改成 1）
- 新乡操作只走标准 `/robot_task`，去掉 `halfbodychemical`；主流程按图：试管1，再试管2与检测放料位移并行，然后检测启动、取料位移、取料完成
- 流程开头增加「等待外部命令」，收到 `PROCESS_BEGINS` 后才往下跑；图上没有把结束连回开头时跑完即停，不再自动重开
- RESET 不再新建 Modbus Slave，沿用同一块寄存器/线圈数据区
- 开盖、关盖、检测、清洗的布尔信号在模块状态到位后由上位机复位：开盖启动等到状态 2、开盖取料完成等到状态 0；关盖启动等到状态 2、关盖取料完成等到状态 1；检测四路分别等到状态 2、3、5、1；清洗启动等到状态 2、清洗取料完成等到状态 1

### 流程引擎与编辑器

- 画布支持复制粘贴功能块：`Ctrl+C` 复制、`Ctrl+V` 粘贴（放在右下方，连续粘贴逐次错开）、`Ctrl+D` 原地再生一个。副本带全部参数但不带连线；在输入框或弹窗里不抢这三个键；粘贴可 `Ctrl+Z` 撤销
- 修：`RESET_SYSTEM` 在用并行状态机的 7 个项目（展厅 / 新乡 / ConST / WRC / WRC_FLOW / ATC / AJL）上报 `'ParallelTaskStateMachine' object has no attribute 'reset'`，重置只做一半——机器人已断开，配置却没重载。通用重置流程调的 `reset()` 只有单机状态机有，并行状态机补上同名入口
- 修：同样 7 个项目上 `GET_TASK_STATE` 带 `target_cmd_id` 查指定任务时报 `get_state() takes 1 positional argument but 2 were given`。并行状态机的 `get_state` 补上可选的任务 id 参数，查不到时返回与单机一致的「未找到」结构（界面只发不带参的查询，所以此前没撞上）
- 运行控制里点「启动」「重置系统」不再把 Mock 开关拨开；只有点开关本身才会拉起或关掉 mock
- 打开图形化页面时选中 `robot_config.json` 里的 `active_project`，不再固定停在列表第一项 WRC_FLOW
- 从节点面板拖功能块到画布时，换项目或改点位后不再叠出多块（画布 drop 监听只绑一次）
- Mock / 演练等直接 `fetch` 的接口漏带登录令牌，已登录维护者也会被当成未登录使用者
- 通用 PLC 模块：S7、Modbus TCP 与新乡原 Modbus 服务端共用 `plc_read` / `plc_write` / `plc_wait` / `plc_handshake`，协议和地址只写在配置里，换协议不动图；「PLC 读取」可一次读多个连续字
- 通用 HTTP 发送、通用机器人动作（导航 / 操作 / 状态记录）的处理器提到基础层，新项目直接组装，不用各自重写一遍；通用功能块在所有项目的侧边栏都能看到
- 修：并行支路或子流程里的节点失败后，整条流程仍报「执行完成」——分液、检测失败会被当成一轮正常跑完。现在报失败并指出是哪个节点
- 修：并行支路与子流程内部的节点不写进执行记录，上层扫记录查不到真正失败的那个（展厅 23 个节点的图只留下 8 条）
- 修：支路里条件判否或走失败分支抵达汇合点时越过了汇合屏障，把汇合点及其后继又在支路线程里跑了一遍
- 登录入口在工具栏右上角；登录弹窗改为独立排版（角色说明、口令框、回车提交）
- 可同时开账号登录与口令登录：登录框里切换；开发者口令可配多条（各自项目范围），保存/激活日志记下是谁改的
- 账号改为本机明文生成密封包：现场只验签；`/config/auth_accounts.pack` 可整份覆盖出厂包；去掉口令查询接口

## 3.0.3 — 2026-09-10

### CONST_FLOW

- 装表编排从 Python 整块封装拆到三张子流程图：`const_install_station` / `const_install_once` / `const_uninstall_once`；主图仍是一个块，双击可进子流程改顺序和重插次数
- 机器人装表/拆表/导航改用通用功能块；MQTT 让位、合龙、识别结果等仍用 ConST 专有节点
- 子流程用 `role: "subflow"` 标记，不参与「只能激活一份入口流程」；保存时补回 `id`/`name` 等元信息，避免子流程被误当成第二入口
- 表掉落不再算动作失败，图上分支转呼人工；重插前拆表补齐上位机让位/合龙
- 检定系统 MQTT 与可选 PLC 分开：无独立 Modbus 时可关 `plc.enabled`
- 让位/合龙点对点 MQTT 超时后，若 live 工位状态已到位则视为成功，避免上位机已合龙却误呼人工；呼叫人工节点保留真实原因（不再把 MQTT 超时写成表掉了）
- MQTT 意外重连后自动重新订阅回复主题；`requestId` 兼容写在 `data` 里

### KAIAO / KAIAO_FLOW

- 走廊中间点：近 AGV 货架格（`shelf0_3` / `shelf1_3`）持箱去 agv_car 时，后退并校正后再远离货架平移，避免转 90° 撞架
- 货架互搬：有箱则后退 → 转向零件车 → 目标正前方 → 转向进入；空手则后退后直达
- 上述参数可在图形化「运行控制 → 配置文件」里按字段注释修改，与点位写在同一份 KAIAO `robot_config.json`

### 流程引擎与编辑器

- 并行节点支持在汇合点汇齐后再继续；演练可取消
- 流程图中文 id、激活开关、子流程下拉与「打开子流程」；`set_variable` 支持加减
- 信号别名（如 `manual_reset` ≡ `MANUAL_RESET_COMPLETED`）
- 机器人 WebSocket 重连补上 rosbridge 子协议，避免 mock 上 HTTP 400 刷屏

### WRC_FLOW

- `simple_line` 现场装配流程调整
