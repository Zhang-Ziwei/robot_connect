# flow_editor —— 拖拽式机器人流程编辑器（零依赖前端）

## 为什么是纯 HTML/CSS/JS，不用 React/Vue

生产环境是打包进 Docker 的嵌入式/工控设备，不保证有 Node.js/npm 构建环境。
本目录下的 `index.html` / `style.css` / `app.js` 都是浏览器能直接运行的原生代码，
没有任何构建步骤——复制这三个文件到任何一台装了 `network/flow_api_server.py`
的机器上就能用，迁移部署不受工作环境限制。

如果以后确实需要更复杂的交互（比如更丰富的画布手势），也可以在这个基础上
逐步引入构建工具，`network/flow_api_server.py` 只是把这个目录整个当静态资源
吐出去，不关心里面用了什么技术栈。

## 使用方式

```bash
python -m network.flow_api_server
# 浏览器打开 http://<设备IP>:8099/
```

这样只起编辑器进程，画图、校验、改点位、改配置和「演练」都够用。

但「🤖 运行控制」里的按钮不一样：它们是按现有 HTTP 命令协议**转发给主程序的业务命令端口**（默认 8090），主程序没跑就会报「无法连接业务命令服务」。要用那一组按钮，直接跑主程序即可，它会把命令端口和本编辑器一起起来，不需要再单独起上面那条命令：

```bash
python main.py          # 命令端口 8090 + 编辑器 8099
```

编辑器刻意不自己碰机器人，就是为了不绕过主程序里既有的校验、状态机和日志。

打开后点工具栏「📖 使用说明」，会弹出带线框高亮的交互式新手引导。换镜像 / 升级前点「⬇ 输出」把流程下载到本机，更新后再用同一按钮「导入」迁回。

## 一份界面服务所有项目：差异写在哪

`flow_editor/` 下的三个文件（`index.html` / `app.js` / `style.css`）是**唯一一份界面代码，不按项目分叉**。全文没有 `if (project === 'KAIAO')` 这类判断，项目名只出现在注释和几句提示文案里。界面上所有的项目差异，都是后端把「这个项目长什么样」描述成 JSON 发过来、前端照着渲染的。

所以想调整某个项目的界面，**不要改 `app.js`**，按下面三层找对应位置。

### 第一层：项目描述表（最常改的地方）

`network/flow_api_server.py` 顶部，每个项目一个 `_load_<项目>_adapter()` 函数，注册进 `PROJECT_ADAPTERS`。改按钮、改下拉框选项、改提示语都在这里。

| 字段 | 决定界面上的什么 |
|---|---|
| `display_name` | 项目下拉框里显示的中文名 |
| `local_flows_dir` | 流程列表读哪个目录 |
| `project_node_schemas` | 侧边栏「项目专有」栏的节点及其参数表单 |
| `common_nodes` | 侧边栏「通用」栏显示哪几个通用节点 |
| `known_handler_types` | 保存前校验「这个节点类型本项目有没有处理器」 |
| `dryrun_adapter` | 「演练」按钮用哪套 mock 与自动信号 |
| `poses_project` / `poses_config_dir` | 「📍 点位」面板读写哪份点位配置 |
| `robot_options` | 节点参数里「机器人」下拉框的选项 |
| `step_options` | 「记录状态步骤」的步骤名下拉框；给空数组就退化成自由文本 |
| `service_options` | 「发送操作动作」的 Service 通道下拉框 |
| `command_options` | 「等待外部命令」的事件名下拉框 |
| `exclusive_enabled_flow` | 是否强制「只能激活一份入口流程」 |
| `run_control` | 「🤖 运行控制」的按钮、分组、二次确认文案、命令模板、放行的命令白名单 |

还有三个**可选**字段，只有需要的项目才写，不写就没有该行为：

| 可选字段 | 作用 | 目前谁在用 |
|---|---|---|
| `graph_validator` | 项目自定义的保存前图校验（例如 ConST 要求标记装表后必须能走到消表） | CONST_FLOW |
| `hidden_node_types` | 处理器还留着兼容旧图，但不在侧边栏显示 | CONST_FLOW |
| `waypoint_config_key` | 点位之外再挂一份参数（走廊中间点） | KAIAO_FLOW |

### 第二层：节点定义（`programs/<项目>/node_handlers.py`）

`NODE_TYPE_SCHEMAS` 写项目专有节点的参数表单，`COMMON_NODES` 声明本项目支持哪些通用节点，`STEP_OPTIONS` / `SERVICE_OPTIONS` 提供下拉框内容。参数表单的字段格式见下面「节点参数表单是怎么'自动'生成的」。

通用节点的界面和处理器都在基础层（`core/common_nodes.py` 配界面，`core/robot_nodes.py`、`core/http_nodes.py`、`core/plc_nodes.py` 配处理器），项目只在 `COMMON_NODES` 里声明用哪几个，不用重写。声明制的原因是：面板上不该出现本项目没有处理器的块，否则拖上去要等跑起来才报「未知节点类型」。

各项目当前的用量，可以看出通用层摊薄了多少工作：

| 项目 | 通用节点 | 专有节点 |
|---|---:|---:|
| 展厅 ZHANTING | 8 | 0 |
| 新乡 XINXIANG | 8 | 1 |
| ConST CONST_FLOW | 3 | 19 |
| WRC_FLOW | 3 | 3 |
| KAIAO_FLOW | 2 | 4 |

### 第三层：现场配置（`programs/<项目>/robot_config.json`）

机器人连接、导航点位、PLC 点表、端口这些**现场会变**的东西。这一层开发者和使用者都能在界面上「🤖 运行控制 → 配置文件」里直接改，不用动代码。

### 数据怎么流到界面

前端启动后依次请求下面这些接口，拿到的就是上面三层合成的结果；静态页面本身由同一个服务从 `flow_editor/` 目录直接托管，零构建、零打包。

```
GET /api/projects              项目列表与 display_name
GET /api/projects/<p>/node-types   侧边栏节点及参数表单（已注入点位/机器人/步骤等动态下拉项）
GET /api/projects/<p>/flows        流程列表与图内容
GET /api/projects/<p>/poses        点位面板
GET /api/projects/<p>/run-control  运行控制的按钮与提示
GET /api/projects/<p>/robot-config 配置文件编辑器
```

### 加一个新项目要动的地方

1. `programs/<新项目>/` 下放 `node_handlers.py`、`dryrun_adapter.py`、`constants.py`、`robot_config.json`、`flows/`
2. `network/flow_api_server.py` 加一个 `_load_<新项目>_adapter()` 并注册进 `PROJECT_ADAPTERS`
3. `infrastructure/config_loader.py` 和 `infrastructure/pose_loader.py` 里登记项目目录
4. 界面代码一行都不用改

## 不同分辨率的适配

界面在 1366×768 的笔记本和 2K/4K 屏上都要能用，做法分两层：

**外壳 UI 跟着屏幕缩放。** 根字号按视口宽度线性变化
（`clamp(12px, 0.28vw + 10.2px, 17px)`，1366 宽约 14px、2560 宽封顶 17px），
两侧栏宽度同样用 `clamp` 给出上下限，所以小屏上不会被两栏吃掉大半画布，
大屏上也不会出现一条窄得可笑的侧栏。整体高度改用 flex 分配，
不再是 `calc(100vh - 44px - 160px)` 那种一改工具栏高度就错位的写法。

**画布内容不跟着屏幕变，改为手动缩放。** 节点的 `x`/`y` 是存进流程 JSON 的数据，
若节点尺寸随屏幕浮动，同一张图在不同机器上的排布观感就不一致了。
所以画布另配缩放控制：工具栏的 `−` / `＋` / `⤢ 适应`，或 `Ctrl`(⌘) + 滚轮。
缩放以鼠标位置为锚点，放大时不会把内容甩到左上角去。

窄屏（<1180px）下属性面板改为浮在画布上方而不是挤占宽度；
两侧栏都可以点标题栏的 `«` / `»` 折叠，折叠后画布边缘会浮出一个小按钮用来展开。

## 节点参数表单是怎么"自动"生成的

每种节点类型（不管是引擎内置的 `condition`/`delay`/... 还是项目专属的
`navigate`/`send_operation`/...）都在后端提供一份 JSON schema：

```json
{
  "label": "条件分支",
  "category": "控制流",
  "fields": [
    {"name": "var", "type": "text", "label": "变量名（支持 {{var}} 模板）", "required": true},
    {"name": "op", "type": "select", "label": "比较符", "options": ["==","!="], "default": "=="}
  ],
  "outputs": ["true", "false"]
}
```

前端 `renderInspector()` 拿到这份 schema 后按 `fields` 逐个生成表单控件
（`text` → 文本框，`number` → 数字框，`select` → 下拉框，`checkbox` → 勾选框，
`json` → 文本域 + JSON 解析，常用于数组/对象类参数），不需要给每种节点类型
单独写一份表单代码。

**改完参数立刻写回节点内存**（监听 `input` / 勾选的 `change`），不必等失焦。
点画布或别的节点会拆掉输入框，如果只听 `change`，没失焦的改动会丢。
所以点到别处之前，当前正在改的字段已经进了 `node.params`；要持久化仍须点「💾 保存」。

新增/修改一种节点类型的参数表单，只需要改后端 `NODE_TYPE_SCHEMAS`
（`programs/<PROJECT>/node_handlers.py`）里的 `fields` 定义，前端完全不用改。
这就是"编辑页面可以自己定制"的实现方式——你完全可以在这里继续加自定义的
`type`（比如颜色选择器、点位拾取器）来满足更复杂的定制需求。

## 功能区块配色

节点按 schema 里的 `category` 上色（左侧色条 + 类型名文字色），左边节点面板
用的是同一套颜色，所以"面板里的某一类"和"画布上的某个节点"能对上号：

| 分类 | 颜色 |
|---|---|
| 控制流 | 蓝 `#4c8dff` |
| 机器人动作 | 绿 `#35c471` |
| 流程辅助 | 紫 `#c07cf0` |
| 状态记录 | 黄 `#f2c14e` |

项目自定义的新分类不用改前端：`app.js` 的 `CATEGORY_COLORS` 里没登记的分类会
按分类名排序从备用色板里稳定取色（不会每次刷新都变）。想固定某个分类的颜色，
在 `CATEGORY_COLORS` 里加一行即可。

## 连线规则

- 每个节点左侧是入端口，右侧是出端口。
- 普通节点只有一个出端口（"out"）。
- `condition` 节点有两个出端口：绿色 = true 分支，红色 = false 分支。
- 拖动出端口到目标节点的入端口上松开鼠标即可连线；同一个出端口只能连一条边
  （再连一条会替换旧的）。
- **点击一条连线会选中它**（高亮成蓝色粗线），右侧属性面板显示它的起点/终点、
  分支（`when`，可以直接改），并提供删除按钮；也可以选中后按 `Delete` 键删除。
- **选中一个节点时**，属性面板底部会列出与它相连的所有连线（入边/出边），
  每条都能"查看"（定位选中）或直接"删除"。画布上连线密集时点线容易点偏，
  这个列表是更可靠的入口。
- `parallel` 节点的分支不是普通连线，而是写在它参数表单的"分支起始节点 id 列表"
  （JSON 数组）里——一个并行节点可能同时展开多条完全独立的子链路，用普通连线
  表达容易和 `success`/`failure` 出边混淆。为了不让并行起点看起来"孤零零、
  看不出带起了哪几条分支"，画布上会按这个数组补画一组**紫色虚线**：
  从 parallel 节点右下角发出，指向各分支的起点节点。这些虚线同样可以点击查看，
  "删除"它等同于把对应节点从 `params.branches` 数组里移除。

## 键盘快捷键

| 按键 | 作用 |
| --- | --- |
| `Delete` | 删掉选中的节点或连线 |
| `Ctrl+Z` | 撤销（最多回退 50 步） |
| `Ctrl+Y` / `Ctrl+Shift+Z` | 重做 |
| `Ctrl+C` | 复制选中的节点 |
| `Ctrl+V` | 粘贴，放在原块右下方；连续粘贴会逐次错开，不会叠在一起 |
| `Ctrl+D` | 原地再生一个选中的节点（相当于复制 + 立即粘贴） |
| `Ctrl`（⌘）`+ 滚轮` | 缩放画布 |

复制粘贴只处理**一个**节点，和画布的单选模型一致。几点行为说明：

- 副本带着原块的全部参数（深拷贝，改副本不影响原块），但**不带连线**——
  连哪里得自己拉。新 id 由 `类型_序号` 自动生成。
- 剪贴板是页面内部的变量，不走系统剪贴板。参数里常有多行 JSON，经系统剪贴板
  要处理读写权限和解析失败，而画布内复制本来也不需要跨标签页。
- 光标在输入框里、或有弹窗打开时，这三个键一律放行给浏览器，`Ctrl+C` 仍然是
  复制文字。
- 复制 `parallel` 节点时，副本的 `params.branches` 会被清空，当成一个空并行块。
  否则副本会带着原块的分支列表，被自动补出一批指向原支路的紫色虚线，变成两个
  并行块同时带起同一批分支。
- 粘贴和再生都能用 `Ctrl+Z` 撤销。

## 未保存修改的保护

画布上的任何改动（增删节点/连线、改参数、拖动位置）都只在浏览器内存里，不点
"💾 保存"就不会写回服务器。为此：

- 有未保存改动时，顶部流程下拉框会显示成 `流程名（未保存）`，保存成功后立刻恢复。
- 切换流程、切换项目、新建流程前会弹窗询问：**保存并继续 / 放弃修改 / 取消**。
  选"取消"会把下拉框恢复成原来的选项，不会误切走。
- 直接关标签页或刷新时，浏览器会弹出自带的"离开此网站？"确认。

## 身份与权限

工具栏右上角有身份栏时，说明设了口令、权限管理已启用。未登录是「使用者」：
能看流程图、能启停调度、能改现场配置，但改流程图/点位/演练的按钮会置灰，
鼠标悬停能看到具体原因（分「没这个权限，请先登录」和「这个项目没授权」两种）。

点「登录」提权，**只输口令、不用账号名**，口令本身决定是开发者还是维护者。
开发者只能改被授权的项目——切到别的项目时保存按钮会重新置灰，提示里会列出授权范围。

**没有身份栏**说明没设口令（权限管理未启用），此时所有人拥有全部权限。
设口令在维护者本机编辑 `PACK_DELETE/auth_accounts.json`，运行
`python3 PACK_DELETE/make_auth_pack.py`，把生成的密封包放到镜像或现场 `/config`。
详见 `readme_files/权限与账号.md`。

按钮置灰只是别让人点到注定被拒的操作，真正的拦截在后端逐接口做。

## 流程激活开关

编辑器里可以保存多张图（展会正流程、备选方案、测试图）。**外部命令只跑打开了「激活」的那份**，开关写在流程 JSON 顶层 `enabled`，不写死在代码里。

- 下拉里标「激活」的才会被 `PROCESS_BEGINS`（或该项目对应业务命令）执行。
- 打开要跑的流程，点「○ 激活」。WRC / CONST 同一时刻只能激活一份（打开这份会关掉其它）。
- KAIAO 可以同时激活多张（不同命令各一张）；关掉的备选图不会响应命令。
- 未写 `enabled` 的旧图视为已激活。展会新建图默认不激活，避免盖掉正在用的那份。
- **PROCESS_BEGINS 是流程总开关**（`robot_config.flow_control.require_process_begins`，默认 true）：
  START_WORKING 只连机器人，不会自动开跑。上位机项目有自己的开任务指令时把该项设为 false。

## 导航点位（📍 点位）

点位坐标存在 `robot_config.json` 的 `navigation_poses.<项目>` 段里，原来只能手改
文件。现在可以在编辑器里直接改：每行一个点位，左边是点位名，右边是坐标 JSON，
支持新增/删除。坐标格式与 `infrastructure/pose_loader.py` 的校验规则一致：

```jsonc
[[x, y, z, qx, qy, qz, qw]]            // 单段：直接走到这个点
[[...], [...]]                          // 多段：按顺序途经多个点
```

保存时后端会先校验格式（必须是 7 个数字的数组或其列表），不合法直接拒绝并列出
具体哪个点位有问题，避免写出一份会让主程序回退到硬编码默认值的配置。写入位置
沿用现有分层：挂载了 `/config/robot_config.json` 就写外部文件，否则写项目内置
配置；写入前自动备份旧文件。

保存成功后，`navigate` 节点的"目标点位"下拉框会自动刷新，新点位立刻可选，不用刷新
页面——因为这个下拉框的选项不是写死在代码里的，而是后端返回节点 schema 时按
`robot_config.json` 当前内容实时生成的（schema 里把字段标成 `"options_source": "poses"`
即可，见 `programs/WRC_FLOW/node_handlers.py`）。

点位弹窗顶部有 **「当前导航位姿」** 一块（和下面的点位表分开）：「读取当前位置」按钮
和只读坐标区。临时连配置里的机器人，订阅导航里程计
`/zj_humanoid/navigation/odom_info`（`ROSTopic.ROBOT_MOTION_STATE`），把当前位姿显示出来，
**不写入点位表**。导航未开、该话题无数据时会失败，不会改去读底盘 odom。

接口：`GET /api/projects/<项目>/current-pose`（也可 `GET|POST .../poses/current`，
query 或 body 可带 `robot_id`）。

> **注意**：正在运行的主程序仍在用它启动时加载的点位。改完要发 `RESET_SYSTEM`
> 命令热重载（见 `infrastructure/pose_loader.reload_active_project_nav_poses`），
> 或者重启主程序，新点位才会生效。

### 新增点位为什么需要项目开启 `allow_extra_keys`

`pose_loader` 有一套防呆机制：配置文件里出现代码 `defaults` 之外的点位名，默认会被
当成**拼写错误**警告并忽略。对点位集合写死在代码里的传统项目这是对的，但对支持在
界面上增删点位的项目就会导致"新点位存进了配置却永远不生效，导航时报未知点位"。

所以这类项目要在自己的 `constants.py` 里显式开启：

```python
load_nav_poses(project="WRC_FLOW", defaults=_WRC_FLOW_POSE_DEFAULTS,
               project_config_dir=..., allow_extra_keys=True)
```

同时把项目名加进 `infrastructure/pose_loader.ALLOW_EXTRA_POSE_KEYS_PROJECTS`，
`RESET_SYSTEM` 热重载才会用同样的规则。开启后新增点位仍然要过格式校验
（7 元坐标或其列表），格式不对照样会被拒绝。

KAIAO / KAIAO_FLOW 同样开了 `allow_extra_keys`：编辑器里给 KAIAO 地图加的点位
会写进 `programs/KAIAO/robot_config.json` 的 `navigation_poses.KAIAO`，运行时也会加载。
`KAIAO_FLOW` 激活时 `reload_active_project_nav_poses` 会按 KAIAO 那一份热重载。

## 真实流程运行控制（🤖 运行控制）

这个面板控制的是**真实主程序**，不是顶部的「▶ 演练」。它自己不碰机器人，而是把按钮
翻译成现有的 HTTP 命令，转发给业务命令端口（默认 8090，即 `main.py`）。

**「启动」发 `START_WORKING`**：连接已配置的机器人、下发导航地图等初始化；成功后
调度进入工作状态，机器人随时可以接收业务命令。业务命令不走这个按钮。

**「重置」发 `RESET_SYSTEM`**：主要作用于调度系统本身，抹掉任务状态、忙闲、
持箱/货架重量等记忆参数，并回到休眠。不是发给机器人的业务动作；之后需再次启动。

| | WRC_FLOW | KAIAO_FLOW |
|---|---|---|
| ▶ 启动 | `START_WORKING` | `START_WORKING` |
| 业务命令 | `PROCESS_BEGINS` 等，由 WCS / 其他设备下发，或用面板里的「模拟 HTTP 发送」 | `PICK_BOX_TO_SP` 等，同样由外部下发或模拟发送 |
| 暂停 / 恢复 / 结束 | 面板按钮 | 无（一次性任务） |

模拟发送的模板来自 `test_commands/*.json`，可改 JSON 后再发，效果等同 `curl` 打到 8090。

前提：主程序 `main.py` 正在运行，且 `active_project` 已切到对应项目。主程序没起时
面板会直接提示连不上命令端口。

点工具栏「🖥 主程序输出」会新开一页，实时显示 `main.py` 打到终端的详细
`print`（导航反馈、动作日志等）。文字可用 `−` / `＋` 或 Ctrl+滚轮缩放。
要看到内容必须先启动 `main.py`（它会把 stdout 镜像到 `logs/main_console.log`）；
只跑 `python -m network.flow_api_server` 时页面会提示还没有主程序日志。
用 mock 跑当前画布。mock 由后端按需自动启动，演练结束后自动关闭（本机已有
mock 在听则复用、不关）。演练不会影响任何真实机器人，也**不会**走
`START_WORKING`。接口按 NDJSON 流式推每个节点的开始/结束，画布和日志边跑边
更新，不必等整趟结束。
