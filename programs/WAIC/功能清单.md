# WAIC 项目功能清单

> 中间件接口转发与大任务封装，提供箱子搬运、单步抓放和导航触发等标准 HTTP 接口。

---

## 项目结构

```
programs/WAIC/
├── WAIC.py            # 任务处理器主文件（WAICHandler）
├── constants.py       # WAIC 专属常量（导航点位 / 服务名 / 任务名 / 超时）
├── robot_config.json  # WAIC 项目内置配置（导航点位 / 连接参数等）
└── 功能清单.md        # 本文件
```

## 接收的 HTTP 命令

### 任务接口

| cmd_type | 类型 | 说明 |
|---|---|---|
| `PICK_BOX_TO_SP` | **异步** | 把箱子从 `box_initial_a` 完整搬到 `box_target_area`（导航→抓取→导航→放置）|
| `PICK_UP_BOX`    | **异步** | 导航到 `area` 后执行抓取 |
| `PUT_DOWN_BOX`   | **异步** | 导航到 `area` 后执行放置 |
| `NAVIGATION`     | **异步** | 触发导航，从当前位置导航到 `area` |

**所有任务均为异步**：HTTP 立即返回，后台线程执行，结果可通过以下两种方式获取：
1. **主动查询**：发送 `GET_TASK_STATE` 命令（带 `target_cmd_id`）
2. **被动回调**：任务完成/失败后自动 POST 结果到配置的回调 URL（见下方回调配置）

**所有任务接口的 `params` 中均支持 `robot_id` 字段**（可选，默认为 `"robot_a"`）：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `robot_id`         | string | 否 | 指定执行任务的机器人 ID，如 `"robot_a"`、`"robot_b"`，默认 `"robot_a"` |
| `area`             | string | 是（单点接口）| 目标点位名称，对应 `navigation_poses.WAIC` 中的 key |
| `box_initial_area` | string | 是（PICK_BOX_TO_SP）| 取箱点位名称 |
| `box_target_area`  | string | 是（PICK_BOX_TO_SP）| 放箱点位名称 |

> **所有接口均为异步**：立即返回 `success=True`，任务在后台线程执行。  
> 结果获取方式：① 主动查询 `GET_TASK_STATE`；② 被动回调（配置后自动推送）。

### 任务完成回调

WAIC 的四个异步任务完成（或失败）后，会通过 `handlers.callback_sender.CallbackSender` 主动向外部系统发送 HTTP POST 回调。

**启用方式**（`robot_config.json`）：

```json
"callback": {
    "enabled": true,
    "url": "http://192.168.1.100:8099/callback",
    "timeout": 10,
    "retry": 3,
    "retry_interval": 10
}
```

| 字段 | 说明 |
|---|---|
| `enabled` | 是否启用回调 |
| `url` | 回调目标完整地址（含 IP/端口/路径） |
| `timeout` | 单次 POST 等待对方响应的超时（秒） |
| `retry` | 未收到确认时的重发次数 |
| `retry_interval` | 两次发送之间的间隔（秒） |

**回调 Body（POST）**：

```json
{
    "cmd_id":   "PICK_BOX_TO_SP_001",
    "cmd_type": "PICK_BOX_TO_SP",
    "success":  true,
    "message":  "搬运完成: point2 → point3"
}
```

| 字段 | 说明 |
|---|---|
| `cmd_id`   | 原始命令 ID（即发送任务时的 `cmd_id`）|
| `cmd_type` | 命令类型，如 `PICK_BOX_TO_SP` |
| `success`  | `true` 表示成功，`false` 表示失败/异常 |
| `message`  | 结果描述（失败时包含错误原因）|

**对方响应（须 HTTP 200）**：

```json
{ "received": true }
```

未在 `timeout` 内收到上述确认，或连接失败时，将间隔 `retry_interval` 秒后重发，最多 `retry` 次。

**本地测试接收服务器**：

```bash
# 启动（监听 8099，与 robot_connect 的 callback.url 配置匹配）
python3 tools/callback_server.py --port 8099

# 同时记录日志
python3 tools/callback_server.py --port 8099 --log callbacks.jsonl
```

> 服务器源码：`tools/callback_server.py`（回调发送方：`handlers/callback_sender.py`）  
> 全量命令说明见：[命令接口一览](../../readme_files/命令接口一览.md)

### 通用查询接口（由基础层提供，无需 WAIC 实现）

| cmd_type | 说明 |
|---|---|
| `GET_TASK_STATE`         | 通过 `target_cmd_id` 查询任务运行状态 |
| `GET_ROBOT_MOTION_STATE` | 通过 `robot_id` 查询机器人里程计（位置/姿态/速度）|
| `GET_BATTERY_STATE`      | 通过 `robot_id` 查询机器人电池电量 |

## 接口详细说明

### PICK_BOX_TO_SP（异步）

**功能**：完整搬箱大任务。后台依次执行：  
`导航到初始区` → `抓取箱子` → `导航到目标区` → `放置箱子`

**请求**：
```json
{
  "header": {"seq": 1, "stamp": {"secs": 1696000000, "nsecs": 0}, "frame_id": "map"},
  "cmd_id": "PICK_BOX_TO_SP_001",
  "cmd_type": "PICK_BOX_TO_SP",
  "params": {
    "robot_id": "robot_a",
    "box_initial_area": "point1",
    "box_target_area": "point2"
  }
}
```

**响应**（立即返回）：
```json
{
  "success": true,
  "code": 0,
  "action_type": "PICK_BOX_TO_SP",
  "description": "",
  "message": "动作 PICK_BOX_TO_SP 执行成功"
}
```

**查询进度**：
```json
{
  "cmd_type": "GET_TASK_STATE",
  "params": {"target_cmd_id": "PICK_BOX_TO_SP_001"}
}
```

## 导航点位配置

点位坐标在 `programs/WAIC/robot_config.json` 的 `navigation_poses.WAIC` 节中配置：

```json
"navigation_poses": {
  "WAIC": {
    "home":   [[x, y, z, qx, qy, qz, qw]],
    "point1": [[x, y, z, qx, qy, qz, qw]],
    "point2": [[x, y, z, qx, qy, qz, qw]],
    "point3": [[x, y, z, qx, qy, qz, qw]],
    "point4": [[x, y, z, qx, qy, qz, qw]],
    "point5": [[x, y, z, qx, qy, qz, qw]]
  }
}
```

**加载优先级（高→低）**：
1. `/config/robot_config.json` — Docker 外部挂载配置（现场调试）
2. `programs/WAIC/robot_config.json` — 项目内置配置
3. `infrastructure/robot_config.json` — 基础兜底配置

> 多段路径示例（途经中间点再到终点）：  
> `"point1": [[x_mid, y_mid, ...], [x_end, y_end, ...]]`

如需增加新点位（如 `point6`），需同时在以下两处声明，否则防呆机制会忽略 config 中的定义：
1. `programs/WAIC/constants.py` 的 `_WAIC_POSE_DEFAULTS` 字典（加入占位坐标）
2. `programs/WAIC/robot_config.json` 的 `navigation_poses.WAIC` 节（填写实际坐标）

## 职责分层原则

| 层级 | 文件 | 职责 |
|---|---|---|
| 分发层 | `programs/TJSH/cmd_handler.py` | HTTP 命令接收 → 路由到 `WAICHandler` |
| 业务层 | `programs/WAIC/WAIC.py` | 任务流程编排（导航 + 服务调用 + 触发回调）|
| 回调层 | `handlers/callback_sender.py` | 任务完成后 POST 回调，等待 `received:true` 确认，失败重发 |
| 配置层 | `programs/WAIC/constants.py` | 服务名、任务名、超时、点位加载 |
| 点位层 | `programs/WAIC/robot_config.json` | 导航点位坐标（可现场覆盖）|
| 底层   | `hardware/navigation_utils.py` | 导航 Action 封装（全项目公用）|

## 启动项目

在 `infrastructure/constants.py` 中设置：

```python
DEFAULT_ACTIVE_PROJECT: str = "WAIC"
```

或在 Docker 外部配置 `/config/robot_config.json` 中添加：

```json
{
  "active_project": "WAIC"
}
```

> `ALL` 模式下 WAIC 命令与其他项目命令同时注册，适用于多项目并行场景。
