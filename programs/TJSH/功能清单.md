# TJSH 项目功能清单

> 通用机器人调度系统的核心命令处理器，同时负责化工实验室分液 / 转运任务的具体业务逻辑。  
> 两台机器人协作：**robot_a** 负责转运，**robot_b** 负责分液。

---

## 项目结构

```
programs/TJSH/
├── cmd_handler.py      # 核心命令处理器（CmdHandler）—— 所有项目共用的 HTTP 命令路由
├── constants.py        # TJSH 专属导航点位（NavigationPose），从 robot_config.json 动态加载
├── robot_config.json   # TJSH 项目内置导航点位配置
├── pose_lock.py        # 双机器人点位互斥锁（防止冲突点位同时操作）
├── 功能清单.md          # 本文件
└── __init__.py
```

> `cmd_handler.py` 同时作为系统总路由器，将 ATC / AJL 命令分发到对应处理器：
> - `programs/ATC/ATC.py` → `ATCHandler`
> - `programs/AJL_anjielun/AJL.py` → `AJLHandler`

## 接收的 HTTP 命令

### 系统控制

| cmd_type | 说明 |
|---|---|
| `START_WORKING` | 系统激活，允许接收后续任务命令 |
| `STOP_WORKING` | 停止所有任务，系统回到休眠状态 |
| `GET_TASK_STATE` | 查询当前任务状态（支持指定 `robot_id`）|
| `GET_ROBOT_MOTION_STATE` | 查询机器人实时位姿（Odom 信息）|

### 转运任务（robot_a）

| cmd_type | 说明 |
|---|---|
| `SCAN_QRCODE` | 扫描二维码 + 抓取样品瓶放入后部暂存区 |
| `TRANS_SAMPLE` | 将后部暂存区瓶子转运到分液台 |
| `TRANSFER_SPLIT_DONE_BOTTLE` | 将分液完成的瓶子从分液台暂存区转运到存放区 |

### 分液任务（robot_b）

| cmd_type | 说明 |
|---|---|
| `SPLIT_SAMPLE` | 从待分液区抓瓶子 → 分液台分液 → 放到对应暂存区（250ml / 500ml）|
| `SPLIT_SAMPLE_V2` | 分液任务升级版（多步骤版本，含前进 / 后退进入点位）|

### 跨项目命令路由

| cmd_type | 路由目标 |
|---|---|
| `TRANS_COMPONENT` · `PROCESS_BEGINS` 等 ATC 命令 | `→ ATCHandler` |
| `AJL_START_TASK` · `AJL_STOP_TASK` | `→ AJLHandler` |

## 导航点位（`NavigationPose`）

所有点位从 `robot_config.json` 动态加载，硬编码值作为兜底。

| 属性名 | 说明 | 状态 |
|---|---|---|
| `SCAN_TABLE` | 扫描台（含中间点 → 终点，多段路径）| ✅ 已有坐标 |
| `HOME_ROBOT_A` | robot_a 归位点 | ✅ |
| `TASK_PREPARE_WAITING_SPLIT_AREA_TRANSFER` | 待分液区任务准备点（转运）| ✅ |
| `WAITING_SPLIT_AREA_TRANSFER` | 待分液区（转运任务点位）| ✅ |
| `SPLIT_DONE_250ML_AREA_TRANSFER` | 250ml 分液完成暂存区（转运）| ✅ |
| `SPLIT_DONE_500ML_AREA_TRANSFER` | 500ml 分液完成暂存区（转运）| ⚠️ 占位符，需填写 |
| `HOME_ROBOT_B` | robot_b 归位点 | ✅ |
| `TASK_PREPARE_SPLIT` | 分液任务准备点位 | ⚠️ 占位符，需填写 |
| `WAITING_SPLIT_AREA_SPLIT` | 待分液区（分液任务点位）| ✅ |
| `WAITING_SPLIT_AREA_SPLIT_FORWARD` | 待分液区前进进入点 | ⚠️ 占位符，需填写 |
| `EMPTY_BOTTLE_AREA_SPLIT` | 空瓶区（分液任务点位）| ✅ |
| `EMPTY_BOTTLE_AREA_SPLIT_FORWARD` | 空瓶区前进进入点 | ⚠️ 占位符，需填写 |
| `SPLIT_LIQUID_AREA_SPLIT` | 分液台（分液任务点位）| ✅ |
| `SPLIT_LIQUID_AREA_SPLIT_FORWARD` | 分液台前进进入点 | ⚠️ 占位符，需填写 |
| `SPLIT_DONE_250ML_AREA_SPLIT` | 250ml 分液完成暂存区（分液）| ✅ |
| `SPLIT_DONE_250ML_AREA_SPLIT_BACK` | 250ml 暂存区后退进入点 | ⚠️ 占位符，需填写 |
| `SPLIT_DONE_500ML_AREA_SPLIT` | 500ml 分液完成暂存区（分液）| ✅ |
| `CHROMATOGRAPH` | 色谱仪点位 | ⚠️ 占位符，需填写 |

> **标注 ⚠️ 的点位**需根据实际地图，在 `programs/TJSH/robot_config.json`（或 Docker 外部 `/config/robot_config.json`）的 `navigation_poses.TJSH` 节填写坐标后重启。

### 修改点位坐标

```json
// programs/TJSH/robot_config.json（或 /config/robot_config.json）
{
    "navigation_poses": {
        "TJSH": {
            "WAITING_SPLIT_AREA_SPLIT_FORWARD": [[x, y, z, qx, qy, qz, qw]],
            "SPLIT_DONE_250ML_AREA_SPLIT_BACK":  [[x, y, z, qx, qy, qz, qw]]
        }
    }
}
```

格式规则：
- **单目标点**：`[[x, y, z, qx, qy, qz, qw]]`（外层 list 包一个 list）
- **多段路径**：`[[mid_x,...], [end_x,...]]`（每个 list 是一个路点，最后一个为终点）

## 点位互斥锁（`pose_lock.py`）

防止 robot_a（转运）和 robot_b（分液）同时在对应点位操作造成机械干涉。

| 转运点位（robot_a 占用时…） | 被阻塞的分液点位（robot_b 等待）|
|---|---|
| `WAITING_SPLIT_AREA_TRANSFER` | `WAITING_SPLIT_AREA_SPLIT` |
| `SPLIT_DONE_250ML_AREA_TRANSFER` | `SPLIT_DONE_250ML_AREA_SPLIT` |
| `SPLIT_DONE_500ML_AREA_TRANSFER` | `SPLIT_DONE_500ML_AREA_SPLIT` |

```python
from programs.TJSH.pose_lock import get_pose_lock

pose_lock = get_pose_lock()
with pose_lock.acquire_pose(robot_id, "WAITING_SPLIT_AREA_TRANSFER"):
    # 执行转运操作，期间 robot_b 无法进入 WAITING_SPLIT_AREA_SPLIT
    pass
```

## 配置文件说明

TJSH 项目配置加载优先级（高→低）：

```
1. /config/robot_config.json                 ← Docker 外部挂载（现场调试用）
2. programs/TJSH/robot_config.json           ← 项目内置（代码仓库随项目一起发布）
3. infrastructure/robot_config.json         ← 基础兜底（含全量点位）
```

`programs/TJSH/robot_config.json` 中仅需维护 TJSH 相关的点位，`robots`、`http_server` 等通用配置以上层文件为准。

### 全项目公共回调（handlers/callback_sender.py）

异步任务（如 WAIC）完成后 POST 结果到 `robot_config.json` → `callback.url`；须收到对方 `{ "received": true }` 确认，否则按 `retry_interval` 重发。  
全量命令与消息示例：[命令接口一览](../../readme_files/命令接口一览.md)
