# AJL 安捷伦色谱仪放样项目功能清单

> 单台机器人执行的色谱盘放样任务，与旧项目完全解耦。

---

## 项目结构

```
programs/AJL_anjielun/
├── AJL.py                  # 任务处理器主文件（AJLHandler）
├── chromatograph_client.py # 色谱仪 AAC HTTP 客户端（ChromatographClient）
├── constants.py            # AJL 专属常量（点位 / 步骤 / 服务名 / API 配置 / 超时）
├── robot_config.json       # AJL 项目内置导航点位配置（navigation_poses.AJL）
├── 功能清单.md              # 本文件
└── __init__.py
```

## 接收的 HTTP 命令

| cmd_type | 说明 | 返回 |
|---|---|---|
| `AJL_START_TASK` / `PROCESS_BEGINS` | 启动放样流程（异步，立即返回）。可携带 `vial_barcode`（样品条码）和 `robot_id` 字段 | `"AJL 放样任务已启动"` |
| `AJL_STOP_TASK` / `PROCESS_ENDED` | 请求停止正在执行的流程，机器人完成当前步骤后干净退出 | `"已发送停止信号"` |
| `PROCESS_PAUSED` | 暂停流程，完成当前最小动作颗粒度后等待 | `"已暂停"` |
| `PROCESS_RESUMED` | 恢复暂停的流程 | `"已恢复"` |

> **注：** 无前缀版本（`PROCESS_BEGINS` 等）仅在 `active_project = "AJL"` 单项目模式下注册；
> ALL 模式下须使用 `AJL_PROCESS_BEGINS` / `AJL_PROCESS_PAUSED` / `AJL_PROCESS_RESUMED` / `AJL_PROCESS_ENDED` 前缀命令，避免与 ATC 命令冲突。

## 任务流程（9 步 API 协议）

```
PROCESS_BEGINS / AJL_START_TASK
    ↓
[Step 0] 导航到 HOME 起始点位
    ↓
[Step 1] 登录 AAC 系统  POST /api/v1/auth/login  ← 仅首次执行一次
    ↓
[Step 2] 同步样品数据   POST /api/v1/Sample/batch
         → 1 个 limsSample（大样品）+ VIAL_COUNT 个 vialList（小样品）
         → 小样品条码 = vial_barcode-001 .. vial_barcode-N
    ↓
[Step 3] 查询仪器       GET  /api/v1/Instrument/query?thirdpartyIdentity=...
         → 解析 data.cdsId（顶层）+ data.injectors[category=="GC_Tray"].id
    ↓
[Step 4] 准备放样       POST /api/v1/Events/ReadyToPlaceVialToInstrument
         → 根据 statusCode 决策：重试 / 等待 / 终止
    ↓
[Step 5] 申请进样器位置 POST /api/v1/Events/ApplyInstrumentPositionToPlaceVial
         → 成功后等待 AFTER_APPLY 秒
    ↓
[检查] 机器人是否已在色谱盘抓取点位？（is_robot_at_pose）
    ├── 是 → 跳过导航
    └── 否 → 导航到 DISC_PICKUP
    ↓
[动作] 抓起色谱盘（pick_disc）
    ↓
[导航] 到色谱仪点位（INSTRUMENT）
    ↓
[并行执行 ─────────────────────────────]
│ [Step 6] 通知放样完成  POST /api/v1/Events/PlaceVialsToInstrumentComplete
│          → 成功后等待 AFTER_PLACE 秒
│ [动作]   放下色谱盘（place_disc）
│ [Step 7] 启动分析      POST /api/v1/Events/StartAnalysis
│          → 获取 AnalysisRunId（可能需要 Step 8 轮询）
│ [Step 8] 轮询 RunId    GET  /api/v1/Analysis/active
│ [导航]   回 HOME 点位
[────────────────────────────────────────]
    ↓
[Step 9] 轮询运行状态   GET  /api/v1/Analysis/{runId}/status
         → 直到 status == "Finished"（最长等 ANALYSIS_MAX_WAIT 秒）
    ↓
流程完成
```

每个步骤均调用 `_check_flow_control()` 检查暂停/停止信号。

## 职责分层

| 层 | 文件 | 职责 |
|---|---|---|
| HTTP 命令入口 | `AJL.py → AJLHandler` | 接收调度命令，启动/停止后台流程 |
| 机器人控制 | `AJL.py → _run_task` | 导航、机械臂动作（ROS service），调用 API 层 |
| API 通信 | `chromatograph_client.py → ChromatographClient` | 只负责 HTTP 请求和响应解析，不含机器人逻辑 |
| 常量 | `constants.py` | 导航点位、步骤枚举、API 配置、超时参数 |

## API 接口速查（`chromatograph_client.py`）

继承自 `network/http_client.py`（`HttpClient`），所有方法返回 `HttpResult`（`success` / `message` / `data`）。

| 方法 | HTTP | URL | 作用 |
|---|---|---|---|
| `step1_login()` | POST | `/api/v1/auth/login` | 登录，获取访问权限 |
| `step2_sync_samples(vial_barcode)` | POST | `/api/v1/Sample/batch` | 同步样品数据 |
| `step3_query_instrument()` | GET | `/api/v1/Instrument/query` | 查询仪器，动态获取 `cds_id` 和 `injector_id` |
| `step4_ready_to_place()` | POST | `/api/v1/Events/ReadyToPlaceVialToInstrument` | 确认仪器可放样 |
| `step5_apply_position(pos)` | POST | `/api/v1/Events/ApplyInstrumentPositionToPlaceVial` | 申请进样器位置（内部等待 `AFTER_APPLY` 秒）|
| `step6_place_complete(vial_barcode, pos)` | POST | `/api/v1/Events/PlaceVialsToInstrumentComplete` | 通知放样完成（内部等待 `AFTER_PLACE` 秒）|
| `step7_start_analysis()` | POST | `/api/v1/Events/StartAnalysis` | 启动仪器分析，尝试获取 `AnalysisRunId` |
| `step8_poll_analysis_run_id()` | GET | `/api/v1/Analysis/active` | 轮询获取 `AnalysisRunId`（Step 7 未返回时使用）|
| `step9_query_run_status(run_id)` | GET | `/api/v1/Analysis/{run_id}/status` | 查询运行状态，`"Finished"` 表示完成 |

## 常量文件速查（`constants.py`）

| 类 | 内容 |
|---|---|
| `AJLNavigationPose` | 导航点位坐标（HOME / DISC_PICKUP / INSTRUMENT），按实际地图填写 |
| `AJLNavTolerance` | 导航精度参数 |
| `AJLService` | ROS Service 名 |
| `AJLTask` | Service 的 task 字段值（pick_disc / place_disc）|
| `AJLArea` | Service 的 area 字段值 |
| `AJLStep` | 任务步骤枚举（供 ParallelTaskStateMachine 使用）|
| `AJLTimeout` | 各阶段超时时间（秒）|
| `AJLApiConfig` | AAC 服务器地址（从 `http_client` 配置动态加载）、认证信息、样品字段、`VIAL_COUNT` 等 |
| `AJLStep4Policy` | Step 4 失败时根据 `statusCode` 决策：重试 / 等待 / 终止 |

## 配置修改说明

### 导航点位配置

`AJLNavigationPose` 在模块加载时从 `robot_config.json` 动态覆盖，硬编码值保留作兜底。

**加载优先级（高→低）：**
```
1. /config/robot_config.json                  ← Docker 外部挂载（现场调试用）
2. programs/AJL_anjielun/robot_config.json    ← 本项目内置配置
3. infrastructure/robot_config.json          ← 全局兜底配置
```

```json
// programs/AJL_anjielun/robot_config.json
{
    "navigation_poses": {
        "AJL": {
            "DISC_PICKUP": [[x, y, z, qx, qy, qz, qw]],
            "INSTRUMENT":  [[x, y, z, qx, qy, qz, qw]]
        }
    }
}
```

**防呆机制：** key 拼写错误或格式非法时打印警告并回退到硬编码默认值，不崩溃。

### API 配置（`AJLApiConfig`，在 `constants.py` 中修改）

| 配置项 | 说明 |
|---|---|
| `AJLApiConfig.BASE_URL` | AAC 服务器 IP / 端口，优先从 `robot_config.json` 的 `http_client` 字段自动加载 |
| `AJLApiConfig.USERNAME` | 登录用户名 |
| `AJLApiConfig.PASSWORD` | 登录密码 |
| `AJLApiConfig.THIRD_PARTY_IDENTITY` | 双方约定的第三方标识（用于 Step 3 查询仪器）|
| `AJLApiConfig.VIAL_POSITION` | 进样器放样位置名（如 `"Pos1"`）|
| `AJLApiConfig.CDS_ID` / `INJECTOR_ID` | 由 Step 3 动态获取并缓存；不建议预先填写固定值 |
| `AJLApiConfig.VIAL_COUNT` | 每次同步的小样品（vialList）数量，默认 5 |
| `AJLApiConfig.LIMS_SAMPLE_SITE` | 采样地点（可选） |
| `AJLApiConfig.LIMS_EQUIPMENT` | 采样设备（可选） |
| `AJLApiConfig.VIAL_ANALYSIS_METHOD` | 分析方法（可选） |
| `AJLApiConfig.VIAL_TEST_CODE` | 检测项目代码（可选） |
| `AJLApiConfig.VIAL_PRIORITY` | 样品优先级（0=正常） |

**AAC 服务器地址加载优先级（高→低）：**
```
1. /config/robot_config.json                    ← Docker 外部挂载
2. programs/AJL_anjielun/robot_config.json      ← 项目内置（host: 10.83.108.109, port: 9100）
3. infrastructure/robot_config.json             ← 全局兜底
4. 硬编码默认值 http://192.168.1.100
```

**样品条码命名规范：**
```
PROCESS_BEGINS 中传入 vial_barcode = "20240619135729-1"
→ step2 limsSample.barCode = "20240619135729-1"
→ step2 vialList[0].barCode = "20240619135729-1-001"
→ step6 / 完成日志使用 place_barcode = "20240619135729-1-001"（第一个小样品的条码）
```

## 依赖关系

| 模块 | 来源 | 说明 |
|---|---|---|
| `ParallelTaskStateMachine` | `core/task_state_machine` | 任务状态机 |
| `send_navigation_action` | `hardware/navigation_utils` | 导航动作 |
| `build_navigation_goal` | `hardware/navigation_utils` | 构建导航目标 |
| `is_robot_at_pose` | `hardware/navigation_utils` | 检查机器人是否在指定点位 |
| `send_service_request_task` | `hardware/robot_controller` | ROS Service 调用 |
| `ErrorCode` / `make_*_response` | `infrastructure/constants` | 响应格式 |
| `CallbackSender` | `handlers/callback_sender` | 全项目公共回调（WAIC 等异步任务使用；须对方返回 `received:true`）|

不依赖 `cmd_handler`、`core/robot_actions`，与旧项目业务逻辑解耦。
